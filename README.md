# Longitudinal Trajectory Analysis in ALF: Bayesian Shared-Parameter Joint Models and Trajectory Phenotypes

Reproducible code for **dynamic** prediction of in-hospital mortality in ICU patients with
acute liver failure (ALF):
extract longitudinal labs from MIMIC-IV -> fit Bayesian shared-parameter joint models
(JMbayes2) -> Day-2 landmark dynamic prediction -> trajectory phenotyping from subject-specific
random effects -> an **eleven-arm head-to-head comparison** against classical statistical models,
large language models, and clinical scores.

> **Data notice**: this repository contains **no patient-level data**. MIMIC-IV is governed by the
> PhysioNet Data Use Agreement; users must complete credentialing themselves and prepare the
> database and cohort file locally. Everything written to `data/` is generated by these scripts.

## 1. Method overview

```
MIMIC-IV (PostgreSQL)
      |  01_extract_longitudinal.py     exact itemid extraction, t0 = ICU admission
      v
Long format: 907,046 rows / 2,501 subjects / 19 markers
      |  02_build_model_data.py         survival table + baseline covariates
      |  03_make_wide.py                person-day wide table (tday 0-14), main R input
      v
jm_long.csv / jm_surv.csv / jm_base.csv / jm_wide.csv
      |
      |-- R/01_univariate_jm.R          3 univariate SPJMs (bilirubin / INR / creatinine)
      +-- R/02_multivariate_jm.R        trivariate JM with shared random effects  *recommended
      |
      |  R/03_landmark_prediction.R     univariate-arm Day-2 prediction (reuses rds)
      |  R/04_mv_repredict.R            trivariate-arm Day-2 prediction (reuses rds)
      |  R/05_trajectory_clustering.R   random effects b_hat -> k-means phenotypes
      v
jm_pred_L2_h{7,14}.csv / jm_mv_pred_L2_h{7,14}.csv / jm_mv_clusters.csv
      |
      |  python/05_calibrate_llm.py     LLM probability recalibration (Platt / isotonic, 5-fold)
      |  python/06_clinical_scores.py   MELD / SOFA / ALFSG score arms
      |  python/07_compare_all_arms.py  eleven-arm AUC-calibration-Brier-DCA summary
      v
all_arms_summary.csv + 4 figures
```

**Three design decisions**

1. **Landmark framework**: the primary analysis sets the landmark at Day 2 (Day 0 coverage is only
   29-35% because blood is rarely drawn immediately at ICU admission; Day 2 reaches 94.5%).
   The prediction target is the conditional risk `P(L < T <= L+h | T > L, trajectory up to L)`,
   which avoids immortal time bias and reverse causation at end of life.
2. **Exact definition of the risk set** (easy to get wrong): exclude subjects with
   `outcome == 1 AND event_time_d <= L`.
   Do **not** filter with `event_time_d > L` -- that wrongly drops patients who were transferred
   out of the ICU within 2 days, have `event = 0`, and are still in the risk set at Day 2.
3. **Multivariate beats "model separately then combine"**: the trivariate model with shared random
   effects across the three trajectories outperforms averaging three univariate models on
   discrimination, calibration, and Brier score simultaneously.

## 3. Configuration

All paths can be overridden by environment variables; defaults point inside the repository:

| Variable | Purpose | Default |
|---|---|---|
| `ALF_ROOT` | repository root | inferred from script location |
| `ALF_DATA_DIR` | data / output directory | `$ALF_ROOT/data` |
| `ALF_COHORT_XLSX` | cohort file | `$ALF_ROOT/cohort/alf_icu_final_first_stay.xlsx` |
| `PGPASSWORD` | **database password (the only supported channel)** | unset |

Database host/port/user can be set at the top of `python/01_extract_longitudinal.py`,
or see `config.example.yml`.
**Never write the password to any file** -- pass it only via `PGPASSWORD`.

You must supply `cohort/alf_icu_final_first_stay.xlsx`: one row per patient, containing
`outcome` (in-hospital death), `gender`, age, etiology, complications, organ support,
and MELD/SOFA.

## 4. Reproduction steps

```bash
# (0) Prerequisites: local access to MIMIC-IV, cohort xlsx in place
export PGPASSWORD=********          # this step only; do not write it to a file

# (1) Extraction and modelling dataset
python python/01_extract_longitudinal.py   # 907,046-row long table
python python/02_build_model_data.py       # jm_long / jm_surv / jm_base
python python/03_make_wide.py              # jm_wide (person-day wide table, main R input)
python python/04_link_identifiers.py       # case_id <-> id bijection

# (2) Joint model fitting (* the slowest step, roughly 45 min)
Rscript R/02_multivariate_jm.R             # trivariate JM  -> jm_mv_fit.rds
Rscript R/01_univariate_jm.R               # univariate comparator -> jm_fits.rds

# (3) Day-2 dynamic prediction and trajectory clustering (reuses saved rds, no MCMC rerun)
Rscript R/04_mv_repredict.R                # -> jm_mv_pred_L2_h{7,14}.csv
Rscript R/03_landmark_prediction.R         # -> jm_pred_L2_h{7,14}.csv
Rscript R/05_trajectory_clustering.R       # -> jm_mv_clusters.csv + elbow / trajectory plots

# (4) Comparator arms and summary
python python/05_calibrate_llm.py          # LLM Platt / isotonic recalibration
python python/06_clinical_scores.py        # MELD / SOFA / ALFSG
python python/07_compare_all_arms.py       # eleven-arm AUC-calibration-Brier-DCA
```

Scripts 05-07 depend on prediction files produced by the comparator arms
(`clinical_pred_full.csv`, `transformer_oof.csv`, `hy4_pred_full.csv`, `ds_pred_run{1,2,3}.csv`).
If you only need to reproduce the **joint model and trajectory parts**, skip 05-07;
01-04 together with everything under `R/` are self-contained.

## 5. Main results (n = 2,326, the all-arm intersection of the 2,331-subject Day-2 risk set)

Three nested sample sizes: **2,508** (full cohort) -> **2,331** (Day-2 landmark risk set) ->
**2,326** (eleven-arm intersection; the joint model could not produce predictions for 5 subjects
with insufficient longitudinal observations, all of whom survived).

**Eleven-arm discrimination (+7d AUC)**

| Rank | Arm | AUC (95% CI) | Calibration slope | Brier |
|---|---|---|---|---|
| 1 | Baseline LR | 0.753 (0.728-0.778) | 0.76 | 0.1731 |
| 2 | Baseline FT (Transformer) | 0.752 (0.728-0.777) | 0.76 | 0.1780 |
| 3 | ALFSG | 0.732 (0.705-0.759) | 0.96 | 0.1276 |
| 4 | **JM-mv (trivariate)** | **0.722 (0.694-0.751)** | **1.02** | **0.1301** |
| 5 | Hy4 (raw / calibrated) | 0.701 | 0.68 -> 1.00 | 0.2748 -> 0.1332 |
| 6 | JM (univariate union) | 0.700 (0.671-0.729) | 1.34 | 0.1336 |
| 7 | DeepSeek (raw / calibrated) | 0.668 -> 0.667 | 0.53 -> 0.99 | 0.4834 -> 0.1362 |
| 8 | SOFA | 0.632 | 0.99 | 0.1388 |
| 9 | MELD | 0.601 | 0.98 | 0.1411 |

**Three core findings**

1. **The LLM deficit is a probability-scale failure, not a ranking failure, and it is cheaply
   fixable.** DeepSeek's calibration slope is only 0.53 with Brier 0.483; after Platt calibration
   the slope is 0.996 and Brier 0.136 (a 3.5-fold improvement), **while AUC barely moves
   (0.668 -> 0.667)**. A large Brier gain with unchanged AUC is diagnostic evidence that the
   failure occurs in the scaling step.
2. **Explicitly modelling correlated evolution beats modelling separately and combining.**
   JM-mv versus the univariate union: AUC +0.022, calibration slope 1.34 -> 1.02 (correcting
   overdispersion), Brier 0.1336 -> 0.1301.
3. **Trajectory phenotypes are orthogonal to cross-sectional scores.**
   k-means (K = 3) on the random effects b_hat yields three phenotypes whose baseline MELD
   medians are nearly identical (25.3 / 26.5 / 27.7), yet in-hospital mortality differs
   almost threefold (21.2% / 32.4% / **63.0%**).
   This explains why MELD reaches only AUC 0.601 on this dynamic task: it measures state at a
   single time point, not the direction or speed of evolution.

## 7. Implementation notes and pitfalls already fixed

These are the traps hit during this project, documented so they are not repeated:

- **`predict.jm` errors with "last available time is larger than the maximum time to predict"**
  The cause is that `last_times` is taken from the **survival event time** in `newdata`
  rather than from the longitudinal `tday`.
  **Correct approach**: keep only `tday <= L` in the longitudinal part of `newdata`, reset the
  survival columns to `event_time_d <- L, event <- 0` (the risk set is alive at L by definition),
  then `p[p$tday == L + h, "pred_CIF"]` is the conditional cumulative incidence.

- **`mvglmer` is not required.** GLMMadaptive >= 0.9 removed `mvglmer`, but JMbayes2 supports
  multivariate models **natively**: pass `list(fmB, fmI, fmC)` (three `lme` objects) directly to
  `jm()`. No Rtools or legacy compilation needed.

- **`ranef()` has no method for `jm` objects and returns NULL.** The correct place to obtain
  subject-specific random effects is `jm_obj$statistics$Mean$b` (matrix n_subj x q, row order
  matching `levels(jm_obj$model_data$idT)`). `model_info$frames` is an empty list, not lme objects.

- **Subject id types are inconsistent**: `jm_wide$id` is integer, while `ranef` rownames and
  `idT` levels are character. Unify with `as.character()` before `%in%` or `merge`.

- **Marker itemids must use exact mapping, never substring matching**: the AST substring also
  catches Gastrin/Blasts, and Lactate also catches LDH.
  The verified mapping is in `python/01_extract_longitudinal.py`.
